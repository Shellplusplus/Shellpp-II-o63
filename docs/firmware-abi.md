# 固件 ABI

目标 AP 运行时 Thumb 入口：native_app_register_core 0x2C63B391；activitymanager_page_register 0x2C60E9E1；activitymanager_page_unregister 0x2C60D141；Activity activate 0x2C60F0F9；close 0x2C60F3AD；launcher_page_insert_icon 0x2C40EC9D；app_launcher_add(uint16_t) 0x2C412425；launcher_page_main_update_layout 0x2C414C89；register_driver 0x2C6FE05D；miwear_system_reboot(tag) 0x2C63E831。模块别名空间中的 0x0C63B391、0x0C412425、0x0C63E831 等不能与 AP 运行时地址混用。0x2C63E895 已确认是 miwear_system_poweroff，禁止用于软重启。

App descriptor 固定 0x40 字节：+0x08 package_name，+0x0C app_path/resource，+0x10 uint16 app_id，+0x1C resolve_display_name(app*)，+0x20 可空私有槽；+0x00/+0x04、+0x30、+0x34、+0x3C 初始清零。Page descriptor 固定 0x74 字节。当前最小页面按 O63 内置模板预置 +0x00 prototype=0x3C2040D0、+0x10 page_name、+0x14 page_id、+0x16 app_id、+0x28=0、+0x29=5、+0x2A=0、+0x2C Activity API=0x3C203FF4、+0x38/+0x48 初始为零、+0x4C create callback、+0x64 cleanup callback。注册器会补齐 +0x28=4、+0x29=4、+0x2A=2、+0x48 prototype 以及缺省 Activity/lifecycle 链。+0x34 lifecycle 和 +0x40/+0x44 管理器链表由 Activity Manager 管理。组合 ID 为 (app_id << 16) | page_id。

App/Page descriptor 必须位于模块生命周期内的永久可写存储；被引用字符串必须保持稳定。0x3C2E94C0 是可能为空的 Quick App watcher/install loop；0x3C2E94B4 是 async wake handle，不是 loop。静态队列入口为 0x2C31AFD5、0x2C31B0CD；loop 为空时当前实现使用同步 VFS/AP 调用上下文。当前 build marker 为 0x53494937。

页面显示使用已验证的 LVGL/LVX Thumb 入口：page_title_create 0x2C5274E9、page_content_create 0x2C4547AD、row_create 0x2C51F9B9、row_init 0x2C52E1A1、row_update 0x2C52702D、object_align/object_align_to 0x2C41C6F9/0x2C41E155、object flags 及 event_add 0x2C417E0D。目标为 466x466 圆屏。每页标题直接挂到 Activity root；标题下方创建 `366x300` page-content，将 SCROLLABLE 标志重新打开。type-8 原生 row 全部挂到该内容容器，第一行相对容器顶部居中，后续行相对上一行 OUT_BOTTOM_MID +8；row_init 和 row_update 后不覆盖固件计算出的尺寸。这样标题不参与内容滚动，所有动态内容共享同一坐标系，不会再跨父对象相对定位。

`0x2C4961B8` 的 type-3 页面依赖额外的 `366x68`、`368x84` 前置对象，不适合直接截取 row 部分复用。此前把 type-3 row 放进固定容器并在初始化后强制设为 `360x92`，会使外框尺寸和 row 内部 label 几何不一致，是旧版挤压的根因。当前改用已验证的 type-8 row，统一置于滚动内容容器且不覆盖 row 几何。目录页每个逻辑页读取四个条目，分页步长为 4，并追加独立 Previous/Next 行；文件名按 UTF-8 边界缩略到 15 字节，正文最多三条显式换行。CPU、Memory 和 About 使用 332 px 安全宽度的独立 label 页面。

系统通知使用 notification_insert 0x2C643DE5（模块别名 0x0C643DE5）。0x2C643694 的管理器实现明确把 +0x00/+0x04 作为 64 位 UID、+0x08 作为消息 ID，并按 UID 查找或更新记录；Shell++ 使用专用 UID 0x00CD0001。+0x0C/+0x10/+0x14 保存稳定来源、标题和正文；+0x1C/+0x20 留空以选择固件默认图标；+0x48 是详情 UI 创建回调 `(message, root)`，+0x4C 是详情清理回调，+0x50 byte 当前固定为 0，只保留通知中心记录，不请求占满圆屏的前台提醒；+0x54 保存稳定 context，reminder listener 保持关闭。独立前台提示使用真实函数入口 0x2C545E6D（模块别名 0x0C545E6D）：`create_toast(builder, user_data, clickable, context, style)`；当前传入 NULL user_data/context、clickable=0，builder 创建 `220x52` 居中 label。notification_insert 失败为 -102，toast 同步 builder 未创建成功为 -103。软重启使用固件托管入口 miwear_system_reboot("shellpp_ii")，而不是关机入口或直接写 SCB AIRCR；完整顺序见 call-flows.md。
